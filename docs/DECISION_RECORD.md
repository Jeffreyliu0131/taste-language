# Taste Language 关键决策记录

这份记录说明当前公开 demo 为什么这样设计，以及这些取舍带来的后果。它不是需求验证或发布批准。

## 1. 只描述照片视觉偏好

**决定：** 固定“独自长时间学习”情境，只描述照片中可见的构图、光线、视觉边界和物件层次。

**原因：** 照片无法证明噪声、插座、座椅舒适度、拥挤、价格、时段或店规。

**后果：** 输出不能升级为真实地点推荐，也不能从选择推断人格或敏感属性。

## 2. 先用显式、确定性的 feature-difference baseline

**决定：** Ranker 只使用 manifest 中预先登记的 `openness` 和 `density`，不使用 visual embedding 或黑箱模型。

**原因：** 低自由度机制更容易检查数据来源、预测方向、拒答原因和反例。

**后果：** 它只能演示有限的视觉轴，不能代表完整审美。未来若加入 embedding，必须作为独立机制比较，而不是静默替换 baseline。

## 3. 合法输出是 0-2 个候选轴

**决定：** 每个轴独立通过权重、支持样本和冲突检查；信息不足时允许 0 个轴。

**原因：** 为了界面丰富而强行生成语言，会把不确定性包装成个性化洞察。

**后果：** 0 轴和 `abstain` 是正常结果，不是 delivery failure。未见照片预测概率恒为 `null`。

## 4. 在未见照片前一次冻结

**决定：** 第 6 组训练选择后，同时冻结 profile、未见照片预测、0-2 个轴、候选语言位置和方向交换顺序。

**原因：** 若在看到未见照片 response 或语言选择后重算，结果会混入事后信息。

**后果：** 后续接受、改名、否定、合并或撤销只改变表达视图，不改写冻结结果。若要修改训练输入，必须重新开始。

## 5. 运行时不接入 AI 或外部 provider

**决定：** 使用本地确定性模板生成候选标签；核心路径无需模型、API 密钥、账户或网络。

**原因：** 当前要验证的是交互与机制边界，不是模型文案能力。Provider 会引入不可重复输出、数据处理、延迟和失败语义。

**后果：** Adapter 只保留为受限接口，不能修改 canonical profile、证据或预测。未来 provider 必须显式评估，不能继承当前 demo 的可信度。

## 6. 三份记录不合成总分

**决定：** 分别呈现照片选择、语言辨认和运行状态。

**原因：** 语言看起来贴切、未见照片方向相同和系统成功运行是三件不同的事。

**后果：** 界面和 JSON 都不输出综合成功率、雷达图或个性化分数。

## 7. UI concealment 不称盲法

**决定：** 在相应步骤前不在 UI 或 ARIA 中展示预测与候选来源，但明确称为 `UI-concealed`。

**原因：** 数据仍存在于客户端 state，开发者工具可以读取。

**后果：** Demo 不能用于 participant-grade blind research。正式研究需要独立进程或服务端角色隔离。

## 8. Local-first，但不把 localStorage 称安全边界

**决定：** Session 保存在单一、版本化的 localStorage envelope；损坏和 bundle mismatch fail closed，并支持导出和明确重置。

**原因：** 本地运行降低部署和数据传输复杂度，同时允许恢复与审计演示。

**后果：** localStorage 不提供机密性、防篡改、多用户隔离或取证级删除。正式部署需要新的存储与威胁模型。

## 9. Evidence verdict 保持 Validate first

**决定：** 公开 demo 可以展示机制，但不得宣称需求、准确率、反通用描述、编辑价值或商业价值已经验证。

**原因：** 这些结论需要真实目标用户行为和预先定义的验证方法，不能由代码完成度替代。

**后果：** 当前仓库不是 production-ready 产品，也不是正式研究工具。下一步应先验证问题与增量价值，再决定是否扩大投入。
